# Нативный клиент

Swift 6 package для macOS 26+. Содержит библиотеку контракта/локального API и запускаемый SwiftUI executable LifeTrackerDesktop (D-006.1). Экран показывает серверный баланс, четыре показателя, источник, время и подробности. Есть нейтральный векторный силуэт человека, без выдуманных бафов/медицинских выводов. Есть частичный ввод самооценок, история и исправления с optimistic concurrency (D-006.2). Устанавливаемый `.app` остаётся D-006.3.

```sh
sh tools/test_macos.sh
```

Зависимостей сторонних пакетов нет. Адрес локального сервиса и owner credential передаются снаружи; токены не хранятся в исходниках. HTTP transport и UI проходят дополнительные проверки при подключении D-005/006. Swift tools version задаёт минимальный язык; конкретная версия компилятора видна в журнале CI.

Скрипт использует выбранный `xcode-select` toolchain. Для Command Line Tools он добавляет пути к поставляемому Testing.framework и его runtime; глобальная конфигурация системы не меняется.

## Запуск окна разработчиком

Сначала запустите [локальный host](../core/LifeTracker.Host/README.md). Во втором терминале из корня проекта:

```sh
LIFETRACKER_RUNTIME_ROOT="$PWD/var/profile" sh tools/run_macos.sh
```

Порт по умолчанию 17841; при изменении задайте одинаковый LIFETRACKER_PORT для host и UI. Desktop читает owner.credential из общего абсолютного runtime-root, без печати и копирования токена. При отсутствии конфигурации показывает экран подключения; после исправления окружения перезапустите executable. Это developer launch, не установка в Программы.

Обновление — при открытии, активации окна, раз в минуту и вручную. Просроченный серверный snapshot не показывается как текущий баланс; числа сохраняются в карточках с обозначением необходимости обновления. Ошибка соединения оставляет последний snapshot и явный статус ошибки. Клиент не пересчитывает баланс или приоритет источников. Подробности открываются нажатием на карточку. Lifecycle и финальная RPG-графика пока не реализованы; визуальная/UI E2E-приёмка не объявляется пройденной.

## Запись и история

«Отметить состояние» открывает форму: включите нужные показатели, задайте значения 0–10 с шагом 0,5, время состояния и необязательный комментарий. В историю загружается 50 записей; «Загрузить ещё» продолжает серверный snapshot, «Обновить историю» начинает новый. Исправление требует причины и сохраняет новую ревизию; при конфликте обновите историю и откройте запись заново.

Перед HTTP-отправкой payload/идентификатор атомарно сохраняются в desktop-pending-assessment.json внутри runtime-root. Если ответ потерян, повтор использует ту же команду, в том числе после перезапуска клиента. Новые изменения заблокированы до разрешения этой отправки. Подтверждённый completed receipt удаляет журнал; явное HTTP 4xx-отклонение разрешает исправить ввод. Повреждённый журнал не удаляется автоматически. Файловая блокировка ограничивает запись одним desktop-процессом на runtime-root. Незавершённая форма до нажатия «Сохранить» пока не сохраняется.

Интеграционная проверка Swift-клиента/модели экрана с настоящим host на отдельном синтетическом профиле:

```sh
python3 tools/smoke_macos_client.py src/core/LifeTracker.Host/bin/Debug/net10.0/LifeTracker.Host.dll
```

Она запускает выделенный LiveAssessmentTests; обычные Swift-тесты пропускают его без адреса тестового host. В CI отдельный шаг поднимает host и выполняет этот тест. Это HTTP/presentation integration, не автоматизация кликов SwiftUI.
