# Нативный клиент

Swift 6 package для macOS 26+. Содержит библиотеку контракта/локального API и запускаемый SwiftUI executable LifeTrackerDesktop (D-006.1). Экран показывает серверный баланс, четыре показателя, источник, время и подробности. Есть нейтральный векторный силуэт человека, без выдуманных бафов/медицинских выводов. Есть частичный ввод самооценок, история и исправления с optimistic concurrency (D-006.2). Локальный `.app` собирается и устанавливается tools/package_macos.py; визуальная приёмка ещё открыта.

```sh
sh tools/test_macos.sh
```

Зависимостей сторонних пакетов нет. Адрес локального сервиса и owner credential передаются снаружи; токены не хранятся в исходниках. HTTP transport и UI проходят дополнительные проверки при подключении D-005/006. Swift tools version задаёт минимальный язык; конкретная версия компилятора видна в журнале CI.

Скрипт использует выбранный `xcode-select` toolchain. Для Command Line Tools он добавляет пути к поставляемому Testing.framework и его runtime; глобальная конфигурация системы не меняется.

## Запуск окна разработчиком

Сначала запустите [локальный host](../core/LifeTracker.Host/README.md). Во втором терминале из корня проекта:

```sh
LIFETRACKER_RUNTIME_ROOT="$PWD/var/profile" sh tools/run_macos.sh
```

Порт по умолчанию 17841; при изменении задайте одинаковый LIFETRACKER_PORT для host и UI. Desktop читает owner.credential из общего абсолютного runtime-root, без печати и копирования токена. При отсутствии конфигурации показывает экран подключения; после исправления окружения перезапустите executable. Это developer launch; для установки в Программы используйте процедуру ниже.

Обновление — при открытии, активации окна, раз в минуту и вручную. Просроченный серверный snapshot не показывается как текущий баланс; числа сохраняются в карточках с обозначением необходимости обновления. Ошибка соединения оставляет последний snapshot и явный статус ошибки. Клиент не пересчитывает баланс или приоритет источников. Подробности открываются нажатием на карточку. Owned lifecycle реализован в описанном ниже объёме; финальная RPG-графика пока не реализована; визуальная/UI E2E-приёмка не объявляется пройденной.

## Запись и история

«Отметить состояние» открывает форму: включите нужные показатели, задайте значения 0–10 с шагом 0,5, время состояния и необязательный комментарий. В историю загружается 50 записей; «Загрузить ещё» продолжает серверный snapshot, «Обновить историю» начинает новый. Исправление требует причины и сохраняет новую ревизию; при конфликте обновите историю и откройте запись заново.

Перед HTTP-отправкой payload/идентификатор атомарно сохраняются в desktop-pending-assessment.json внутри runtime-root. Если ответ потерян, повтор использует ту же команду, в том числе после перезапуска клиента. Новые изменения заблокированы до разрешения этой отправки. Подтверждённый completed receipt удаляет журнал; явное HTTP 4xx-отклонение разрешает исправить ввод. Повреждённый журнал не удаляется автоматически. Файловая блокировка ограничивает запись одним desktop-процессом на runtime-root. Незавершённая форма до нажатия «Сохранить» пока не сохраняется.

Интеграционная проверка Swift-клиента/модели экрана с настоящим host на отдельном синтетическом профиле:

```sh
python3 tools/smoke_macos_client.py src/core/LifeTracker.Host/bin/Debug/net10.0/LifeTracker.Host.dll
```

Она запускает LiveAssessmentTests и сериализованные LiveRuntimeTests; обычные Swift-тесты пропускают live cases без адреса тестового host. В CI отдельный шаг поднимает host и выполняет live cases. Это HTTP/presentation integration, не автоматизация кликов SwiftUI.

## Локальный пакет и установка

На Mac с выбранным Apple toolchain:

```sh
python3 tools/package_macos.py build
python3 tools/package_macos.py verify var/build/LifeTracker.app
python3 tools/package_macos.py install var/build/LifeTracker.app --destination "$HOME/Applications/LifeTracker.app"
```

Получается Release build для архитектуры текущего Mac, macOS 26+. Пакет имеет локальную ad-hoc подпись, не notarized release для распространения. Платная учётная запись не нужна; системные защиты не отключаются. Процедура повторяема; побайтовая воспроизводимость сборки не заявляется. Манифест содержит исходный commit и признак незакоммиченных изменений, а целостность sealed bundle проверяет codesign. Внутри клиент, опубликованный Core (managed DLL/deps/runtimeconfig и SQLite dylib для текущей архитектуры), Info.plist, манифест и подпись. Core-файлы перечислены с SHA-256; произвольные файлы, PDB, web.config и native assets других платформ не включаются. Личный runtime-root, credential, модели и БД не копируются; .NET runtime в пакет не включён.

Перед обновлением закройте LifeTracker. Установщик отказывается заменять неизвестный `.app`, пакет с лишними файлами/ссылками и запущенный desktop/Core из целевого bundle. Сначала проверяет staged copy, затем заменяет bundle; при ошибке rename восстанавливает предыдущий, а при невозможности rollback сохраняет предыдущую копию рядом с целью. Папка профиля остаётся отдельно. Первая установка не создаёт и не мигрирует профиль.

Откройте LifeTracker.app через Finder → Программы. Без developer environment появится выбор папки профиля и порта локального сервиса. Выберите папку данных; порт по умолчанию 17841. Клиент запустит встроенный framework-dependent host либо подключится к совместимому уже работающему сервису с credential выбранного профиля. Для запуска требуется установленный .NET 10 / Microsoft.AspNetCore.App 10.0 (на машине разработки это обеспечивает SDK). Путь профиля/порт запоминаются только в локальном UserDefaults приложения, без копирования ключа доступа. При следующем старте используются повторно.

CI собирает и проверяет подпись настоящего пакета, выполняет установку и повторную замену в отдельном временном каталоге. Tooling-тесты проверяют rollback, сохранение предыдущей копии при ошибке восстановления, отказ от постороннего содержимого/ссылок и запущенного приложения. Это не UI E2E: Computer Use не имеет доступа к интерфейсу, поэтому визуальный сценарий «открыть → записать → исправить» остаётся открытым, M2 не объявляется принятой.

## Управление сервисом (D-007.1)

После выбора профиля NativeRuntime сначала проверяет доступность совместимого API. При успешном подключении внешний процесс остаётся вне его владения. Иначе запускается один дочерний dotnet с DLL из bundle, readiness проверяется до 15 секунд; ранний выход/ошибка/тайм-аут не оставляют управляемый процесс. Повторный старт во время starting/ready/stopping блокируется.

Закрытие окна оставляет приложение и сервис работать; menu bar позволяет открыть окно снова. Command-Q / «Полностью остановить LifeTracker» запрашивает SIGTERM только для собственного Process, ждёт до 10 секунд, затем при необходимости завершает тот же дочерний процесс принудительно. Никаких сигналов по сохранённым PID или имени чужого процесса. При подключении к внешнему сервису команда называется «Завершить LifeTracker» и останавливает только клиент. Неожиданный выход собственного сервиса переводит UI в failed; автоматический restart после crash пока не реализован.

В menu bar есть «Запускать при входе» через SMAppService.mainApp. Изменение происходит только по нажатию; статус requiresApproval показывается явно, ошибка не выдаётся за успех. Регистрация на целевой машине и вход в систему не квалифицированы без доступа к GUI. Сборка/установка не включает автозапуск самостоятельно. Поведение регистрации после обновления bundle также требует OS-проверки; при необходимости настройку нужно включить заново.

Фоновая работа здесь означает живой native host после закрытия окна. Telegram, scheduler, inference, sleep/wake reconciliation, восстановление владения после падения desktop и полная R1 lifecycle-приёмка остаются отдельными задачами. Для developer launch можно задать LIFETRACKER_HOST_DLL / LIFETRACKER_DOTNET; tools/run_macos.sh выбирает построенный Debug host. Эти пути не встраиваются в пакет.

LiveRuntimeTests проверяет собственный start → record → stop → restart → retry на настоящем Core из установленного пакета; unit/process tests — присоединение без остановки внешнего процесса, запрет повторного старта, тайм-аут и гонку stop во время probe. Это не UI-клики и не проверка macOS Login Items.

## Следующий срез в develop: wake connection revalidation

Обработчик NSWorkspace.didWakeNotification выполняет authenticated probe, не запускает второй Core и не меняет ownership. Во время recovering/degraded workspace и форма остаются в том же view tree; текущий баланс скрыт до подтверждения подключения. При временном сбое процесс не перезапускается и не завершается, доступна повторная проверка в окне/menu bar. После успеха сводка/история обновляются; запрос refresh, пришедший во время загрузки, выполняется сразу следом, без ожидания следующей минуты. Startup/shutdown deadlines используют активное время SuspendingClock.

Readiness использует отдельную короткую session, а пользовательские API-запросы — обычный timeout. Callback/process tests и live Core revalidation пройдены; реальный OS sleep/GUI ещё не квалифицированы. Scheduler/lease/notification reconciliation не реализованы этим изменением. Эти изменения готовятся в develop и не заменяют установленную beta.1 до нового релиза.

## Offline резервные копии (develop)

В меню «Профиль» и menu bar доступен пункт «Резервные копии…». Остановите подключение кнопкой в окне, предварительно сохранив или закрыв форму. Остановка своего Core ожидает завершения; для внешнего Core требуется отдельная остановка. Pending journal сохраняется на диске, desktop lease освобождается при закрытии workspace. CLI дополнительно проверяет все writers; если ещё жив другой клиент, операция откажет.

«Создать копию» запрашивает исходный профиль, родительский каталог копии и имя новой папки. «Проверить» проверяет выбранную копию. «Восстановить» запрашивает копию и новый каталог профиля. Существующие папки не заменяются; восстановление не меняет UserDefaults и не переключает профиль само. После успеха закройте окно копий и выберите восстановленный каталог на экране подключения.

Работа выполняется отдельным процессом встроенного Core, без shell, вне main actor. Пока процесс работает, отключены операции копирования/запуска и обычное завершение приложения; отмена посреди SQLite snapshot не поддерживается. Force Quit и выключение машины этим не предотвращаются. Сообщение об ошибке не выводит содержимое профиля/credential/stdout/stderr. Состав и ограничения копии — [offline backup](../../docs/architecture/storage/offline-backup.md).

Live Swift/Core test проверяет отказ при живом writer, создание/verify/restore, путь с пробелами, отказ перезаписи и receipt replay без дубля. Это проверка process adapter; клики NSOpenPanel/имени папки, предупреждение о форме, release journal, busy/quit и внешний вид требуют отдельной UI-приёмки. Автоматическое расписание/retention не реализованы. Установленная beta.1 этого экрана не содержит.
