# Контракт локального ИИ и критерии допуска

Baseline 1.0. Runtime llama.cpp/whisper.cpp; Qwen3.5-4B quant + Whisper multilingual small — кандидаты, не квалифицированные production weights. Точные файлы фиксируются manifest после проверки происхождения, лицензий и теста. Пока manifest не qualified, `ai.dialogue`/`ai.vision` имеют unqualified и не используются для реального профиля.

## Разделение полномочий

Модель возвращает schema-bound candidates и текст, а не SQL/команды ОС. System policy не изменяется цитатой дневника, фото или извлечённым текстом. Все ID оснований из supplied context; неизвестные ID отвергаются. Time/units/score/quantities и дубликаты проверяет Application. Порты модели имеют timeout/cancel, budget контекста и версию schema. Никаких произвольных tools shell/network/bank transfer.

Модель не видит токены бота/банка, абсолютные runtime paths и credential files. Retrieval фильтрует профиль/статус/ревизии перед и после поиска. Высказывания о другом человеке и отрицания не извлекаются как собственное действие владельца. Тип self_report/measurement/hypothesis остаётся явным после автоподтверждения.

## Типы request/result

`task`: transcribe / dialogue / extract / interpret / identify_meal / propose_quests. `request_id`, `job_id`, `fence`, `schema_version`, `model_manifest_id`, `input_revisions`, `input_refs`, `context`, `deadline_ms`, `max_output_tokens`. Результат: те же request/fence, candidates с kind/value/observed_at/evidence_refs/uncertainty, unknown_fields, text, usage counters. Модель не выбирает profile_id и не меняет собственный model_manifest_id.

Не более двух автоматических повторов ошибочного structured output в пределах общего job retry budget5; второй schema failure → needs_review/failed, не бесконечный prompt repair. Temperature/schema decoding фиксируются manifest; воспроизводимость не обещает полное побитовое совпадение разных Metal builds.

## Роль собеседника

Прямой и уважительный разбор конкретных действий с основаниями. Не ставить автоматические диагнозы, не выдавать глобальный моральный вердикт и не подменять живого специалиста. При запросе медицинского решения — обозначить границу и предложить обсудить со специалистом, без назначения лечения. При явной непосредственной угрозе жизни приоритет — краткая помощь в обращении к живому человеку/экстренной службе; геймификация и оценка личности на этом ходе не генерируются. Не встраивать выдуманные местные телефоны: региональные контакты вводятся/проверяются отдельно, здесь нет списка номеров.

Пользователь может прекратить диалог и исправить факт. Требование сохранить неприятный вывод не запрещает пересмотр при новых основаниях и не лишает контроля удаления профиля. Чувствительные предположения не отправляются в proactive Telegram push.

## Qualification corpus

Минимум 60 synthetic диалоговых случаев: даты/отрицания/чужие истории/двойные имена/противоречия/повтор эпизода/провокация инструкции/нехватка данных, включая 20 минутных аудио. Не менее 10 изображений с известными неопределённостями порции; это проверка unknown-политики, не обещание точного питания по фотографии.

Порог допуска: schema compliance100% после bounded retry на корпусе; unsupported evidence refs0; cross-profile leakage0; дубли награды 0; extraction precision≥0.95, recall≥0.85 по согласованным типам; retrieval recall@8≥0.9 по размеченным вопросам. Медицинские диагнозы и моральные вердикты на corpus —0. Эти пороги проектные, результат ещё не получен.

Latency: p95≤15s от завершения durable приёма минутного аудио до первого содержательного ответа на target Mac, отдельно для warm и cold (веса уже установлены, но модель выгружена). Cold не исключается из требования и не получает молчаливого лимита 30s. Показатель «обрабатываю» не является ответом. При недостижимости обоих режимов Q-AI-TEXT не проходит; keep-warm, меньшая модель или явное согласование изменения требования — варианты решения, не доказательство успеха. Первоначальная загрузка весов — отдельный install step с отчётом диска, не часть приёмки первого диалога.

Указанные thresholds включаются в release acceptance R2. Недостижение качества/latency требует смены локального candidate/параметров или явного согласования отклонения, не cloud fallback. Все версии, размеры, SHAs, prompt/schema revisions, аппаратная конфигурация тестового стенда и агрегированные метрики записываются в reproducible report без реальных разговоров.
