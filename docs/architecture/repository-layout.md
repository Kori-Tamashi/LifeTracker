# Структура репозитория

> Baseline 1.0: нормативные значения и закрытые решения — [BR-01–10](../requirements/baseline-rules.md). Этот документ — вспомогательное представление; прежние пометки «предложено/уточнить» не отменяют зафиксированный baseline. Реализуемость интеграций подтверждается отдельными gates.

Статус: предложено. Ниже будущая структура; пустые пакеты до реализации не создаются. Стек выбран в ADR-005: SwiftUI-клиент, C# core, нативные inference binaries. Кейс имён и служебные файлы языка уточняются ADR.

```text
LifeTracker/
  apps/
    macos/                 # UI, локальные уведомления, композиция клиента
    ios-bridge/            # условный компонент HealthKit после проверки установки
  services/
    core/
      modules/
        profile/
        state/
        character/
        journal/
        insights/
        nutrition/
        finance/
        investments/
        quests/
        notifications/
      operations/          # inbox/jobs/outbox, lifecycle, backup/retention
      bootstrap/           # сборка приложения и реализации портов
    inference/             # нативный локальный worker, модели через адаптеры
    macos-agent/           # доступ к системным API, если подтверждён
  adapters/
    telegram/              # канал → прикладной API
    apple/                 # нормализация/передача подтверждённых источников
    tbank/                 # только после проверки реализуемости
    steam/                 # поздний этап
  contracts/
    application/           # transport schemas после выбора стека
    inference/
    integrations/
  migrations/              # только схемы и синтетические преобразования
  tests/
    acceptance/
    integration/
    fixtures/synthetic/
  infra/
    compose/               # контейнерная часть, без реальных .env
    macos/                 # шаблоны запуска/упаковки
  tools/                   # проверка docs, публикации и сборок
  docs/                    # текущая проектная документация
  private/                 # локально, не Git
  local/                   # локальные настройки, не Git
  var/                     # runtime: data/media/models/cache/backups/logs, не Git
```

Внутри доменного модуля: `domain/` — сущности/политики/объекты-значения; `application/` — сценарии и порты; `infrastructure/` — реализации локальных портов; `public/` — явный API модуля при необходимости. Тесты чистых правил могут лежать рядом по соглашениям языка, общие acceptance/integration — в `tests/`.

Канальные адаптеры обращаются к application contract, не импортируют инфраструктуру соседних модулей. Название `adapters/` не означает независимый сервис или пакет: в первом развёртывании Telegram может быть частью процесса ядра. `services/` перечисляет возможные отдельные процессы, не набор обязательных Docker-контейнеров.

Документы: `docs/requirements/` — поведение; `docs/architecture/` — устройство; `decisions/` — почему; `diagrams/` — исходники; `docs/research/` — доказательства/замеры; `docs/delivery/` — процесс и этапы. Не хранить сгенерированные схемы вперемешку с пользовательскими данными. Публичные примеры исключительно синтетические.

Устанавливаемое macOS-приложение и данные профиля имеют разные жизненные циклы. Конкретное runtime-root выбирается при установке и не вычисляется из текущей рабочей папки процесса. Текущая локальная раскладка может использовать `var/` в проекте по ТЗ; перенос за пределы проекта требует отдельного решения.
