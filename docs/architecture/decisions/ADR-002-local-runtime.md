# ADR-002 — Локальные процессы и владение записью

Статус: предложено.

## Контекст и варианты

Требуются фон после закрытия окна, Telegram, локальные модели и возможность Docker. Варианты: всё в UI-процессе; вся система в контейнере; гибрид с отдельными нативными адаптерами.

## Предложение

Гибрид: Core Host содержит прикладную логику и фоновые jobs; UI — клиент. Inference worker и системный агент могут быть нативными. Только ядро пишет авторитетную базу; остальные обращаются через контракт. Бизнес-часть в Docker остаётся гипотезой до замеров. iPhone bridge условен до проверки бесплатной установки.

## Последствия

Требуются оркестрация запуска/остановки, версии контрактов и отображение degraded status. Нет необходимости держать UI открытым. Не вводим синхронизацию двух авторитетных баз: будущий перенос ядра на сервер требует нового ADR.

## Проверка и принятие

Замеры памяти, холодного/тёплого запуска, ускорения, вызова host/container, сна/пробуждения и остановки. Если Docker нарушает лимиты диска/ресурсов, сравнить нативное ядро, не отменять локальность. До эксперимента конкретные transport и runtime не приняты.
