# Архитектурные решения

ADR-001/003/004 приняты проектировщиком через ADR-006. ADR-002/005 уточнены native-default и qualification gates в ADR-006. Выбор компонентов остаётся условным по фактической квалификации. Требования о локальности, Clean Architecture, SOLID и GitFlow подтверждены; конкретные способы их реализации проходят проверку.

| ADR | Решение-кандидат |
| --- | --- |
| [ADR-001](ADR-001-modular-core.md) | Модульное ядро и чистая архитектура |
| [ADR-002](ADR-002-local-runtime.md) | Гибридное локальное размещение и один владелец записи |
| [ADR-003](ADR-003-evidence-and-consistency.md) | Ревизии, происхождение, durable jobs и outbox |
| [ADR-004](ADR-004-quality-gates.md) | Проверяемые зависимости, тестовые уровни и CI gates |

| [ADR-005](ADR-005-component-selection.md) | Выбор стека, runtime и условного комплекта ИИ |

| [ADR-006](ADR-006-design-baseline.md) | Freeze baseline1.0, default deployment и закрытие правил |

Новые ADR: контекст → варианты → предложение → последствия → проверка → условие принятия/пересмотра. Выбор языка/СУБД/моделей требует отдельного ADR с экспериментальными основаниями.
