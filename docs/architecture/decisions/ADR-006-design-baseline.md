# ADR-006 — Завершение проектного baseline 1.0

Статус: **принято проектировщиком по поручению пользователя завершить проектирование**, 20 ноября 2026 года. Это не запись о личном утверждении пользователем всех констант и не разрешение обходить qualification gates.

## Решения

1. ТЗ 1.0 + BR-01–10 и finance-design — нормативное поведение. Черновики 0.x заменены; новые численные defaults выбраны в рамках делегирования. Изменения — новая версия/ADR.
2. ADR-001/003/004 приняты как основа модулей, ревизий и quality gates. ADR-002/005 уточнены: native core default, Docker отдельным qualified profile; SwiftUI/.NET10/SQLite/local inference stack сохранён.
3. Нормативные артефакты реализации: module-implementation, schema-v1.sql, OpenAPI v1, AI policy, UX, deployment, acceptance registry и backlog. Дизайн не требует дополнительного угадывания основных формул/сценариев.
4. Self-report/AI estimate/game stats раздельны. TTL6h/пороги, quota/quiet, load/XP/decay/recovery, copy/retention и financial formulas зафиксированы.
5. 15s AI requirement применяется и к cold, и к warm после установки весов. Невыполнение не переименовывается в успех; Q-AI fail и явный пересмотр.
6. Внешние capabilities допускаются отдельными evidence gates. Screen Time не заменяется трекером без решения владельца; R3 без автоматического доступа банка не выпускается; Watch не блокирует R1.

## Почему native default

Предпочтение Docker ранее было предположением пользователя, гибрид и выбор размещения делегированы. Native profile обеспечивает runtime root в структуре проекта, одну файловую среду SQLite, доступ к macOS и меньший набор обязательных сервисов. Это инженерный выбор до замера, не заявление benchmark. Контейнерная переносимость core сохраняется; Docker profile включается после WAL/backup/volume/footprint qualification, а не молча ломает local storage.

## Состояние готовности

Дизайн baseline завершён как пакет требований/контрактов/правил и задач. Runtime/model performance, реальный banking/Apple доступ, package signature и удалённый CI не подтверждены проектными тестами. Их qualification входит в реализацию с явным pass/fail и блокировкой соответствующего релиза. Такое разделение не объявляет невыполнимое требование выполненным.

## Изменение

Появившийся API/benchmark failure изменяет adapter/параметры либо требует scope decision; выбранный бизнес-смысл не меняется скрыто. Политика публикации действует на все артефакты. Эта итерация не создаёт release приложения и не публикует личные данные.
