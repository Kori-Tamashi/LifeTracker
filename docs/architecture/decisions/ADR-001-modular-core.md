# ADR-001 — Модульное ядро и Clean Architecture

Статус: предложено.

## Контекст

Один профиль, несколько каналов, разнородные правила и поэтапное расширение. Нужны Clean Architecture, SOLID и тестирование без устройств/сети.

## Варианты

1. UI с бизнес-логикой и прямой записью в БД: простое начало, трудно разделить каналы и тесты.
2. Микросервисы по каждой сфере: независимые процессы, но распределённые транзакции и сложная эксплуатация.
3. Модульный монолит с чистыми слоями и опубликованными application API.

## Предложение

Вариант 3. Domain не зависит от framework. Application владеет портами, orchestration и транзакциями. Infrastructure реализует порты; adapters преобразуют каналы. Composition root собирает зависимости. Межмодульные обращения не читают чужие таблицы.

## Последствия и проверка

Нужны явные DTO/маппинг и import rules; преимущества — один источник бизнес-правил и простые атомарные изменения. Проверка архитектурным тестом, unit/contract suites. SOLID проверяется ответственностью и заменяемостью, не числом интерфейсов.

## Условие принятия

Согласованная модель R1 и выбранный стек позволяют выразить границы сборкой/пакетами. Пересмотр при реальной необходимости независимо масштабировать/развёртывать модуль, не из-за его размера на диаграмме.
