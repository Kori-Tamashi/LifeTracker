# ADR-004 — Тесты и CI как условие интеграции

Статус: предложено; требование полного тестирования и CI подтверждено.

## Контекст и варианты

Автономная разработка ИИ требует проверяемых результатов. Только manual review недостаточен; только покрытие строк не проверяет интеграции, UI и смысл ИИ.

## Предложение

Многоуровневая стратегия: architecture, domain/application unit, contract, real-store integration, E2E/UI, reliability, restore, AI evaluation и benchmark. Быстрый обязательный CI для PR, полный gate перед редким релизом. Текущий docs-only workflow не называется проверкой продукта.

## Последствия

Нужны синтетические fixtures, fake clock, одинаковые port contracts и отдельный чистый Mac-стенд для целевых тестов. Внешние сервисы не должны делать обычный PR нестабильным. Отключение теста не превращает непроверенный сценарий в passed.

## Проверка и принятие

Внести в изолированные fixtures неправильный импорт, порог и повторный эффект: тесты должны упасть. Проверить восстановление и отчёт required gates. Конкретные библиотеки и coverage thresholds принять со стеком и baseline.
