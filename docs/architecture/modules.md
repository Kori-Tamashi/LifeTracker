# Модули, слои и зависимости

> Baseline 1.0: нормативные значения и закрытые решения — [BR-01–10](../requirements/baseline-rules.md). Этот документ — вспомогательное представление; прежние пометки «предложено/уточнить» не отменяют зафиксированный baseline. Реализуемость интеграций подтверждается отдельными gates.

Статус: предложено. [C4 Component](diagrams/c4-components.puml).

## Направление зависимостей

UI/Telegram/внешний адаптер → прикладной сценарий → доменные правила. Инфраструктура реализует порты, объявленные прикладным слоем. Домен не импортирует UI, Docker, SDK банка, модель ИИ или драйвер БД. Компоновка выбирает реализации портов при запуске.

Чистая архитектура применяется внутри достаточно крупного модуля; не создавать по отдельному интерфейсу для каждой структуры данных. Межмодульный вызов идёт через опубликованный application API, не через чужие таблицы. Для запроса главного экрана допустима read-model, принадлежащая Character/State и собираемая через явно объявленные контракты.

| Модуль | Владеет | Публикует | Не имеет права |
| --- | --- | --- | --- |
| Profile | Настройки и привязка каналов | ProfileSettingsChanged, политики | Хранить произвольные дневниковые факты |
| State | Наблюдения четырёх шкал и выбор источника | RecordAssessment, GetCurrentState, AssessmentRevised | Назначать диагнозы и награды |
| Character | Представление персонажа, игровые эффекты | GetCharacter, ApplyGameEffect | Подменять самооценки игровыми числами |
| Journal | Разговоры, события, люди, принятые извлечения | AcceptMessage, ConfirmExtraction, ReviseEntry | Принимать модельный вывод как медицинский факт |
| Insights | Интерпретации и зависимости оснований | RebuildInterpretation, Explain | Самостоятельно исправлять исходные слова |
| Nutrition | Блюда, порции, оценки и допущения | RecordMeal, RevisePortion | Выдумывать точность КБЖУ |
| Finance | Операции, долг, бюджет и резервы | IngestTransaction, GetBudget, ApprovePlan | Считать кредитный лимит доходом |
| Investments | Портфель и расчётные отчёты | PortfolioSummary, CalculationRun | Исполнять сделки |
| Quests | Назначения и правила адаптации | AssignQuest, EvaluateOccurrence | Передавать модели право выполнить произвольную команду |
| Notifications | Квоты, тихие часы, доставки | ScheduleNotification, DeliveryStatus | Считать два канала двумя напоминаниями |
| Operations | Inbox, jobs, outbox, leases, backup/retention | Статусы и восстановление | Владеть бизнес-формулой баланса |
| Integration adapters | Протоколы источников, checkpoint | Нормализованные команды импорта | Писать напрямую в бизнес-таблицы |

## Ограниченный shared kernel

Только идентификаторы, время, Money и ошибки/метаданные контракта при доказанном общем смысле. `BaseEntity`, универсальный Repository для всех сущностей, общая «таблица всего» и глобальный mutable context не вводятся. Порты репозитория определяются потребностью сценария/агрегата, не отражением каждой таблицы.

## Паттерны и решаемые задачи

- Ports/adapters: заменить канал, модель или внешний сервис без переписывания правил.
- Repository + unit of work: явно выделить границу атомарной записи.
- Inbox/idempotent consumer: повтор доставки не создаёт повторный факт.
- Transactional outbox: запись результата и намерения продолжить работу фиксируются вместе.
- Strategy: версия формулы баланса/наград, когда появляются реальные альтернативы; сейчас достаточно чистой функции.
- Read model: быстрый главный экран без запуска ИИ; материализация только при необходимости.

Доменное событие — внутренняя связь модулей, не обещание публичного Kafka-контракта. На первом этапе нет отдельного брокера и сети между доменными модулями. Выбор хранилища очереди и транзакционной реализации пока открыт.
