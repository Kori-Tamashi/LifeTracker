# Предметная модель

> Baseline 1.0: нормативные значения и закрытые решения — [BR-01–10](../requirements/baseline-rules.md). Этот документ — вспомогательное представление; прежние пометки «предложено/уточнить» не отменяют зафиксированный baseline. Реализуемость интеграций подтверждается отдельными gates.

Статус: предложено. Это логическая модель предметной области, не список ORM-классов и не обязательная иерархия наследования. [Диаграмма классов](diagrams/uml-domain.puml).

## Словарь

| Понятие | Значение |
| --- | --- |
| Profile | Владелец данных и настройки; один активный профиль, готовность к нескольким не означает реализованную многопользовательскую авторизацию |
| Observation | Утверждение об измерении, самоотчёте или действии в определённое время |
| Evidence | Сохранённое основание: фрагмент, идентификатор исходного эпизода, происхождение |
| Interpretation | Пересматриваемый вывод, зависящий от версий оснований |
| BalanceSnapshot | Восстанавливаемая сводка четырёх актуальных показателей; не медицинская оценка |
| GameAttribute | Игровая характеристика, отдельная от ручной/ИИ-самооценки |
| EventEpisode | Уникальный жизненный эпизод; повтор рассказа не создаёт независимое основание |
| QuestOccurrence | Конкретное назначение с датой/окном, отличается от шаблона повторения |
| Revision | Неизменяемая версия содержимого; исправление создаёт следующую, а не стирает след |

## Общие объекты-значения

- `ProfileId`, `EntityId`, `RevisionId`: непрозрачные стабильные идентификаторы. Идентификатор человека в дневнике не равен Telegram user ID.
- `ObservedAt`: время описываемого события; `ReceivedAt`: время приёма; `RecordedAt`: время фиксации версии. Инстанты сохраняются в UTC, календарные правила используют явную зону `Europe/Moscow` по текущему ТЗ.
- `SourceRef`: тип источника, непрозрачный внешний ключ, версия импорта/модели; произвольный секретный payload не является идентификатором.
- `Score`: 0–10 с шагом 0,5; единица и направление шкалы определены видом показателя.
- `Money`: точная десятичная сумма и код валюты; суммы разных валют не складываются без явной котировки и даты.
- `TimeWindow`: начало включительно, конец исключительно. `RuleVersion` сопровождает рассчитанный результат.

## Агрегаты и инварианты

| Агрегат / модуль | Состав и правила |
| --- | --- |
| Profile / Profile | Настройки зоны, автоподтверждения, каналов; изменение версионируется |
| Observation / State | Вид, значение, время, источник, основание, цепочка исправлений. Сохранение как ИИ не превращается в ручное после подтверждения |
| Conversation / Journal | Сеанс и сообщения; медиа — ссылки в MediaStore. Разговор не является одной гигантской транзакцией |
| JournalEntry / Journal | Резюме, извлечённые эпизоды, ссылки на Person; черновое извлечение не входит в активную память до принятия |
| Interpretation / Insights | Текст вывода, статус, качественная уверенность, список конкретных Evidence/RevisionId; несогласие хранится отдельно |
| Person / Journal | Локальная сущность с псевдонимами; слияние требует явной операции, совпадение имени недостаточно |
| Character / Character | Накопленный прогресс и игровые атрибуты; история эффектов, не производная медицинская карта |
| QuestOccurrence / Quests | Назначение, версия правила, срок, состояния, ссылки на подтверждённые действия; изменение не штрафует задним числом |
| GameEffect / Character | Причина, delta, правило, срок действия/обратная операция. Уникальность причины предотвращает повторную награду |
| MonthlyBudget / Finance | Плановый доход, категории, обязательства, резервы, версия плана; предложение ИИ не изменяет принятый план |
| Account + LedgerTransaction / Finance | Счёт и операции с точными суммами/валютой; переводы связываются явно; внешний баланс и вычисленный не смешиваются |
| Portfolio / Investments | Счета, инструменты, сделки, комиссии, налоговые события; расчётные методы пока открыты |
| NotificationEvent / Notifications | Одно событие и отдельные доставки в каналы; дневной лимит считается по событию |
| ProcessingJob / Operations | Статус, этап, попытки, lease, idempotency key; перезапуск не теряет принятое задание |

`Evidence` может пережить удаление исходного аудио как короткая цитата с ссылкой на уже удалённый оригинал и отметкой доступности. Это основание самоотчёта, не независимое доказательство истинности события. Резюме ИИ и его производный вывод не являются двумя независимыми свидетельствами.

## Выбор состояния

Для каждого из четырёх показателей: отфильтровать недействующие версии и будущие события; выбрать последнюю актуальную ручную отметку; если её нет — последнюю актуальную ИИ-оценку; иначе unknown. Срок шесть часов применён к обоим источникам как проектное предложение. Выбор детерминирован по `(observed_at, revision_sequence, id)`; порядок уточняется контрактом, не зависит от случайного порядка БД.

При полном наборе `balance = min(energy, mood, physical_wellbeing, 10 − anxiety)`. При неполном наборе — undefined, а не 0. Снимок содержит четыре выбранных ID версий, алгоритм, `computed_at`, `valid_until`; устаревание наступает без нового пользовательского события, поэтому чтение проверяет срок, а фон публикует обновление. [Временные правила в ТЗ](../requirements/specification.md) остаются предложением до утверждения.

## Связи между сферами

Сон/тренировка → нормализованное наблюдение → оценка выполнения задания → игровой эффект. Событие не меняет число энергии само по себе без отдельного согласованного правила. Финансовая операция → бюджетная проекция → предупреждение; она не меняет характер человека. Ошибка внешнего источника даёт unknown/stale, а не отрицательный факт.

## Исправление и повторяемость

Исправление создаёт новую Revision с автором/причиной; текущая версия одна. Зависимые Interpretation и проекции получают stale и пересчитываются по новым основаниям. Исходная интерпретация остаётся в истории, но не используется как актуальное знание. Удаление профиля — отдельная административная операция, не отмена одного неприятного мнения.

## Степень детализации

State, Journal и Operations описаны для R1/R2. Финансы, питание и квесты — контекстная модель целевого продукта: точные налоговые формулы, правила пропусков и нормы питания ещё не превращены в поля или классы реализации. Физическая модель теперь определена в [storage](storage/README.md), ER-представления — в diagrams. Детальные финансовые правила — baseline finance-design.
