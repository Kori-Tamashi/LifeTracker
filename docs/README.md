# Карта документации

| Папка | Назначение |
| --- | --- |
| `product/` | Цели, аудитория, сценарии, границы и вопросы исследования |
| `processes/` | BPMN XML/DI, каталог процессов и SVG-предпросмотры |
| `requirements/` | ТЗ, требования и критерии приёмки |
| `architecture/` | Архитектура, модель предметной области и границы модулей |
| `architecture/diagrams/` | Исходники C4 и UML; каждая диаграмма имеет статус и область действия |
| `architecture/decisions/` | ADR: контекст, варианты, решение, последствия и статус |
| `integrations/` | Возможности источников, доступы, ограничения и проверки |
| `delivery/` | Этапы, задачи, риски и порядок разработки |
| `research/` | Датированные исследования со ссылками и результатами экспериментов |

## Правила

1. Статусы решений: предложено, принято, отклонено, заменено. Черновик не означает согласование.
2. Требования получают идентификаторы `FR-…` и `NFR-…`; сценарии — `UC-…`; решения — `ADR-…`.
3. Для каждого обязательного требования нужны наблюдаемый критерий приёмки и связь со сценарием.
4. API и ограничения платформ подтверждаем официальными источниками с датой проверки. Идея интеграции не равна её доступности.
5. Диаграммы храним текстом рядом с описанием. Не дублируем одно правило в нескольких документах: используем ссылки.
6. Применяем [политику публикации](delivery/publication-policy.md): в Git только материалы о продукте и синтетические примеры. Интервью и персональные данные — в игнорируемых локальных каталогах.

## Baseline 1.0

Главная карта завершённого проектирования — [DESIGN.md](DESIGN.md). Нормативный порядок: подтверждённые цели пользователя → ТЗ 1.0 → BR-01–10/finance → API/DDL/ADR-006 → вспомогательные представления. Прежние слова «предложено» в вспомогательном тексте означают происхождение решения, не отсутствие выбранного baseline.

Структура кода и направленные зависимости: [module implementation](architecture/module-implementation.md), [layout](architecture/repository-layout.md). Условия фактического допуска источников и моделей — [qualification](integrations/qualification.md). Это невыполненные проверки реализации, не незаданные бизнес-правила.
