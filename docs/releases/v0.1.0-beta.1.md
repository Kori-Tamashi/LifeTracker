# LifeTracker 0.1.0-beta.1 — первая тестовая версия

Ранний prerelease B0 для ручного тестирования macOS-пути. Это не завершённый R1. Начните с отдельной пустой папки данных; не полагайтесь на эту версию как на единственную копию важных записей.

## Что можно проверить

- Персонаж с серверным балансом, четырьмя показателями, источником и временем оценки.
- Частичный ввод 0–10 с шагом 0,5, комментарий и время состояния.
- История, исправление с причиной и сохранением ревизии, повтор без дублей.
- Запуск встроенного Core, menu bar, повторное открытие окна, полная остановка своего сервиса.
- Сохранение профиля между запусками. Beta-настройки папки/порта отделены от прежних development preferences.

## Установка и первый запуск

Требования: Apple Silicon, macOS 26+, установленный .NET 10 с Microsoft.AspNetCore.App 10.0. На машине разработки этот runtime входит в уже установленный SDK. Docker для этой версии не требуется.

1. Полностью завершите предыдущий LifeTracker и его собственный сервис.
2. Скачайте `LifeTracker-0.1.0-beta.1-macos-arm64.zip` и `SHA256SUMS.txt` из Assets этого release. Сверьте SHA-256 архива (`shasum -a 256 <имя архива>`), распакуйте `.app` и поместите в пользовательскую папку «Программы», сохранив прежнюю версию при необходимости.
3. Откройте LifeTracker. Создайте отдельную папку для бета-теста, например `var/beta-1` в локальной рабочей папке проекта; выберите её в приложении. Порт — 17841, если он свободен. Сервис запускается самим приложением.
4. В новом профиле ожидается «нет данных», а не придуманные характеристики.

Подпись локальная ad-hoc, notarization отсутствует. Скачанный пакет может потребовать ручного разрешения macOS; защиты система сборки не отключает. Локально собранная установленная копия также доступна на машине разработки. [Официальное руководство Apple](https://support.apple.com/en-us/102445).

## Первые 10 минут тестирования

1. Отметьте только энергию = 8. Проверьте источник «Самооценка» и отсутствие полного баланса.
2. Добавьте настроение = 7,5, тревогу = 2, физическое самочувствие = 9. Пока все четыре записи свежие, ожидается баланс 7,5 / «Хорошо».
3. В истории исправьте энергию на 6 с причиной. Ожидается новая ревизия и баланс 6 / «Удовлетворительно».
4. Закройте окно; откройте его снова через menu bar. Записи должны остаться, сервис — продолжать работу.
5. Выберите «Полностью остановить LifeTracker», затем откройте приложение снова. Должны восстановиться выбранная папка и записи.
6. При желании отдельно проверьте переключатель запуска при входе. Разрешение macOS и реальный login пока не квалифицированы; сообщите фактический результат.

Версия видна в menu bar. Для обратной связи нужны шаги, ожидаемый/фактический результат, версия macOS и безопасный текст ошибки. Не прикладывайте credential, базу, личный дневник или полный профиль.

## Ограничения

- Нет голосового ИИ, анализа личности, финансов, питания, квестов, Telegram, Apple Health/Screen Time и Steam.
- Сон/пробуждение, восстановление после падения desktop, автоматический backup/restore, миграции/обновление схемы и полноценная диагностика ещё не завершены.
- UI-клики/закрытие окна и Login Items ожидают ручной проверки: Computer Use не имел доступа. Это не выдано за пройденный UI E2E gate.
- При подключении к внешнему сервису завершение LifeTracker не останавливает этот чужой процесс.
- SDK и .NET runtime не вложены в архив. Frameworks macOS предоставляются системой; ARM64-пакет не объявляется универсальным.

Перед ручной страховочной копией остановите все процессы, использующие профиль, и скопируйте его папку целиком. Автоматическое восстановление не является обещанной функцией этой беты. Для возврата к прежнему `.app` используйте отдельный прежний профиль; не открывайте неизвестную схему старым приложением.

## Проверки и артефакты

Release workflow заново проверяет locked dependencies, форматирование, .NET и Swift tests, synthetic HTTP/storage contracts, установку/обновление подписанного пакета и живой start/stop/restart встроенного Core. `evidence.json` содержит SHA исходников, фактические итоги тестов и границы приёмки; `components.json` — инвентарь зависимостей Core; тексты лицензий находятся внутри `.app`. `SHA256SUMS.txt` покрывает опубликованные файлы. Отсутствие GUI-acceptance указано явно.
