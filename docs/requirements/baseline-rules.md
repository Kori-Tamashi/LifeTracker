# Нормативные правила baseline 1.0

Дата: 20 ноября 2026 года. Решения проектировщика по поручению завершить проектирование. Это зафиксированные defaults для реализации; их можно изменить новой версией правила/ADR. Они не выдаются за дословные ответы пользователя. При расхождении черновых предложений и baseline действует этот документ; исходные цели пользователя сохраняют приоритет.

## BR-01. Объём и выпуск

R1: персонаж, самооценки/баланс/история, macOS фон, Telegram для оценок/просмотра/напоминаний, backup/restore, статус интеграций. Screen Time включается только после Q-APPLE-ACTIVITY. Если этот gate не проходит, выпуск R1 как согласованного пользователем результата блокируется до явного решения об альтернативе; рабочую сборку можно тестировать без него. Watch не блокирует R1.

R2: голосовой дневник, память, лента/календарь/недельный отчёт, локальные оценки ИИ, фото питания, полный набор дневниковых функций Telegram. Фото включается при Q-AI-VISION; при неуспехе показывается функция unavailable, а релиз R2 с уменьшенным составом требует записи отклонения и решения владельца. Watch подключается после Q-APPLE-HEALTH без ожидания R3.

R3: автоматические финансы по всем типам продуктов и инвестиционный учёт, только после Q-TBANK. При закрытом gate этап откладывается, не заменяется ручными операциями; R4 может идти после R2 без R3. R4: квесты, опыт, игровые эффекты и адаптация. Steam, геопозиция, мультипользовательский режим, банковские переводы, исполнение сделок и налоговых деклараций — вне baseline 1.0; для них нужен следующий scope, не скрытое обещание.

## BR-02. Оценки

Score хранится целым количеством полубаллов 0–20, API — число 0–10 с multipleOf 0.5. Четыре шкалы: энергия, настроение, тревога, физическое самочувствие. Временное окно `[observed_at, observed_at+6h)`, включая ИИ. Последняя действующая ручная запись приоритетна; затем последняя ИИ, затем unknown. Tie-break: observed_at, recorded_at, ID (лексикографически). Время в будущем отвергается, допустимое расхождение device clock ≤2 минуты нормализуется на now с сохранением исходного timestamp в provenance.

Задний ввод разрешён до любой прошлой даты; в текущем балансе участвует только актуальное состояние. Исправление создаёт версию с expected_revision, не удаляет историю. Удалённая/отклонённая версия не участвует. Баланс — минимум четырёх нормализованных значений, тревога инвертируется. Пороги 6/7.5/9 сохраняются. Нет полного набора — null, никогда «0». История показывает все отметки; среднее дня отображается отдельно только при ≥2 отметках одного вида и не подменяет текущий показатель.

## BR-03. Персонаж

Человек 2D, фиксированный образ baseline, нейтральная анимация ожидания, переходы энергии/настроения по последним актуальным оценкам; если данных нет, нейтральный вид с «недостаточно данных». Игровые атрибуты R4: тело, восстановление, устойчивость, дисциплина, 0–100; старт 50 означает игровой baseline, а не здоровье. До R4 XP/атрибуты не заполняются фиктивными значениями. Самооценки и игровые атрибуты показаны раздельно.

XP cumulative, уровень `1 + floor(total_xp/100)`; открытые уровни/достижения не отнимаются. Buff/debuff имеет причину, время начала/окончания и версию правила. Допустимы только типы из versioned rule catalog. Ни текст ИИ, ни косвенный пульс не меняют показатели здоровья напрямую.

## BR-04. Диалог, факты, память

Голос обязателен; текстовый ответ достаточен, озвучка необязательна. Свободный диалог с уточнением; явное «стоп/не хочу обсуждать» завершает расспросы. Дневник не оценивает моральную ценность человека. Обратная связь прямая, относится к ситуациям, имеет основания и противоречащие примеры. Медицинский диагноз/лечение не генерируются как факт.

Автоподтверждение по умолчанию выключено; при включении принимаются все валидные типы извлечений, включая гипотезы, с сохранением их типа. Pending/rejected/stale не входят в RAG. Интерпретация об устойчивом поведении требует ≥3 независимых эпизодов в ≥2 календарных днях; качественная уверенность low/medium/high отражает достаточность оснований, не статистическую вероятность. High только после ≥5 эпизодов в ≥3 днях и отсутствия неразрешённых противоречий; иные подтверждённые выводы medium. Одно событие даёт описание ситуации, не устойчивую черту. При противоречии confidence снижается или вывод становится disputed/stale.

Несогласие — отдельная запись, не удаление вывода. Фактическая ошибка исправляется с пересчётом; новая информация может изменить неприятную оценку. Merge людей только после разрешённого явного действия владельца; одинаковое имя не достаточно. Для повторных эпизодов ИИ предлагает match, сомнение сохраняется unresolved и не увеличивает evidence count.

Первичный поиск: FTS5+entity links, ≤30 кандидатов, ≤8 эпизодов, ≤2000 токенов контекста. Недельный отчёт готовится в понедельник после 09:00 за предыдущую неделю: динамика самооценок с источниками/пропусками, события, повторения с основаниями, действия и до трёх предложений. Отчёт не является дополнительным напоминанием, пока явно не запланирована его доставка в пределах общей квоты.

## BR-05. Питание

Не более двух уточнений о составе/массе; при недостатке данных блюдо сохраняется без КБЖУ. КБЖУ — оценочный диапазон с порцией и допущениями. Справочник — локальный FoodCatalog, наполняемый только из источника с проверенной лицензией; пока каталог не квалифицирован Q-FOOD-DATA, числовая оценка unavailable, фото/название допустимы. Источник таблиц не подменяется выдуманными значениями LLM.

Суточные цели необязательны, задаются владельцем в настройках (без медицинского подбора ИИ). Никаких обязательных взвешиваний. ИИ предлагает ингредиенты, детерминированный калькулятор умножает значения на массу. Фото — 30 дней после принятия блюда; миниатюра и уникальное основание сохраняются до удаления записи/профиля. EXIF, кроме нужного времени события с согласия, удаляется из рабочей копии.

## BR-06. Квесты

ИИ сам назначает допустимые задания, в том числе по характеристикам, без подтверждения. Rule engine ограничивает: ≤3 активных квестов на день, нагрузка 4 points/day, квест 1–3 points; задачи с покупками, медицинскими назначениями, экстремальными ограничениями питания и произвольными внешними действиями исключены. Владелец сообщает невыполнимость/болезнь, система пересматривает задание без штрафа за ошибочное назначение. Пользователь не обязан «доказывать» болезнь.

Болезнь/отдых: 0 обязательных, ≤1 optional квест на 1 point, без спада. Пауза действует до выбранной даты или явного окончания, если дата не задана; ИИ не снимает её молча. Недостаток данных не считается неисполнением.

Зарядка ежедневно: факт действия, без длительности. Сон: для локального дня D «лечь до 00:00» проверяет отход ко сну в ночь D→D+1; событие в 23:59 D подходит, ровно 00:00 D+1 — нет. Поздно пришедшие данные исправляют исход. Самоотчёт при конфликте дат приоритетен после уточнения, конфликт источников явно сохранён.

Успех: 10 XP и +1 атрибута, определённого шаблоном: зарядка/еда по валидному критерию → тело; сон → восстановление; устойчивость/дисциплина только по конкретному действию из rule catalog. Нет бонусов за одно лишь «хорошее мнение ИИ». Первый подтверждённый пропуск без штрафа; со второго подряд −1 связанного атрибута, максимум −5 за серию шаблона. Пауза/успех обрывает серию. XP/достижения сохраняются. Шкала clamp 0–100 применяется при расчёте проекции; эффекты хранят исходную delta.

Раз в неделю completion ratio только среди известных исходов, min 5. При ≥80% в двух последовательных недельных окнах и отсутствии recovery — +1 point бюджета до max6; <50% — −1 до min1; иначе без изменения. В новых заданиях применяется новое правило, задним числом нет. Revise outcome компенсирует старый reward/penalty и пересчитывает subsequent projection без двойной награды.

## BR-07. Напоминания

Слоты-кандидаты 10:00/15:00/20:00; событие создаётся только при существующей причине (устаревшее состояние, актуальный квест). Не чаще одного reminder event на слот и трёх на день; общая доставка macOS+Telegram считается одним событием. Нет повтора только из-за очередного 6h TTL при отсутствии иной причины. Тихие часы 22:00–09:00 для всей проактивной доставки; ответы на запрос допускаются всегда.

TTL reminder — 2 часа после слота, перенос на следующий день его не оживляет. Недоставленные актуальные события после wake объединяются в одно; слот учитывается в день первой попытки. Budget warning при пересечении 80% и 100% утверждённого лимита, один раз на category/budget revision/band; контекст пересмотра плана не создаёт повтор той же причины без нового пересечения. Кредитные предупреждения: первое новое использование, затем напоминание о due date за 3 дня и в день платежа, объединение по дню. Они отдельны от reminder quota, но ≤1 финансового дайджеста/день; критическая просрочка отображается в UI постоянно. Push содержит краткую формулировку, суммы/чувствительные выводы — по запросу владельца.

## BR-08. Данные и удаление

Аудио/полный текст — 7 дней после successful extraction+acceptance; pending/failed не удаляются по возрасту. Сохраняются резюме, типизированные записи, короткие цитаты-основания, model/rule revision и source metadata. Это ограничение хранения, не обещание сохранить весь смысл.

Backup ежедневно при первом доступном запуске после 09:00 и перед миграцией. Хранить 7 completed суточных снимков и последнюю предмиграционную до успешной приёмки обновления. Только локально в структуре runtime root проекта. Согласованный manifest + база + уникальные медиа; модели/кэш/поисковый индекс не копировать. Еженедельно и перед релизом — restore rehearsal в отдельный каталог. Цели RPO ≤24h активной работы, RTO ≤10 минут для synthetic baseline ≤1 ГБ, проверяются до выпуска.

Экспорт — ZIP с JSONL entities/revisions, manifest/schema versions и медиа, без ключей. Полное удаление профиля с отдельным подтверждением удаляет базу, media/index/jobs/copies; credential refs отзываются/очищаются локально. Удалённые копии пользователя вне управляемого root не контролируются. Резервные копии не являются вторым тайным профилем.

## BR-09. Финансы

Нормативные формулы и учёт — [финансовая спецификация](finance-design.md). Внешняя автоматическая интеграция обязательна, до неё UI не обещает реальный бюджет. Кредитный лимит не входит в доход/собственные деньги. Валюты хранятся исходными; отчёт RUB только при доступной фиксированной котировке источника, отсутствие курса = incomplete, не 1:1.

## BR-10. Технический baseline

macOS 26+ Apple Silicon; условный bridge iOS 26+, данные Watch через HealthKit на iPhone, отдельное watchOS-приложение не нужно. Перенос на старые ОС — отдельная задача. Core .NET 10, API v1, схема БД v1. Патчи/зависимости фиксируются при реализации с совместной сборкой, не выбираются случайно во время запуска.

По умолчанию native Core Host с runtime root `var/` под выбранной папкой проекта. Docker — поддерживаемый альтернативный профиль после Q-DOCKER-STORAGE; этот выбор укладывается в ранее разрешённое гибридное размещение. Он устраняет нерешённый риск одновременного host/VM доступа к SQLite и лишнего диска в baseline. Смена профиля — stop, backup, проверенный restore в целевую среду; одновременно два core не работают.

Автозапуск при входе, закрытие UI не останавливает core/бота; отдельный Stop отменяет/фиксирует jobs и останавливает управляемые inference-процессы. Не завершать чужой Docker Desktop/модельные процессы. Никаких облачных fallback. API loopback; iPhone bridge только по явно включённому локальному pairing, отдельный защищённый endpoint, не через Telegram для Health batch.
