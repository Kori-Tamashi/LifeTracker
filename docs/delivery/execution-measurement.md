## Когда запускать пилот EVM

Сейчас статус **not baselined**: численные BAC/PV/EV/AC, CPI/SPI и дата завершения не определены. Сначала собрать пять сопоставимых измеренных результатов. Затем на одном следующем небольшом этапе зафиксировать версию плана, конечный набор дочерних пакетов, их бюджеты в часах, плановые даты приёмки и доступные рабочие интервалы. Историческую работу исключить из границы пилота.

Для каждого небольшого пакета правило 0/100: его исходный бюджет становится EV только после выполнения заранее определённой приёмки. Для большого пакета заранее выделить дочерние результаты с отдельными бюджетами; не назначать субъективные «90%» после начала. Обязательная, но не проведённая ручная проверка оставляет соответствующий результат непринятым. Автоматически проверенный технический срез может иметь собственную приёмку, если так определено до старта.

На контрольную дату:

- BAC — сумма исходных бюджетов пилота.
- PV — бюджет результатов, которые по baseline должны быть приняты к этой дате.
- EV — бюджет фактически принятых результатов.
- AC — измеренные активные часы исполнения всех работ в границе пилота, включая незаконченные и rework.
- SV = EV − PV; CV = EV − AC; SPI = EV / PV; CPI = EV / AC.

Все величины здесь в часах. При PV=0 или AC=0 соответствующий индекс не определён; при неполных данных не рассчитывается. Деление принятых пакетов на все пакеты — burn-up по количеству, не трудоёмкость и не процент готовности всего продукта. Изменение декомпозиции меняет сопоставимость счётчика и отмечается отдельно.

SPI не переводится напрямую в дни задержки. Начальные EAC/даты не экстраполировать по одному пакету; анализировать качество, blocked time и остаток вместе. Никакие финансовые выгоды или продуктивность относительно человека из CPI не следуют.

Изменение scope/бюджета/дат фиксировать новой версией с причиной, прежним и новым значением; сохранять исходный baseline и отдельно прогноз остатка. Не переписывать план, чтобы убрать уже возникшее отклонение. Отчёт: дата, baseline version, PV/EV/AC или причина unknown, принятые результаты, блокировки, rework и следующий шаг.

Методические источники: [DOE — EVM](https://www.energy.gov/em/earned-value-management), [Microsoft — prerequisites](https://support.microsoft.com/en-us/project/integrate-variance-tracking-into-your-project-change-management-process).
