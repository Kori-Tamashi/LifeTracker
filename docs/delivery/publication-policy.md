# Политика публикации

Любой коммит, ветка, PR, issue, CI-журнал, вложение и релиз должны быть пригодны для публичного доступа. Приватность репозитория не отменяет эти правила. Технические требования и возможности продукта не должны подаваться как сведения о конкретном владельце.

## Разрешено

| Материал | Условия |
| --- | --- |
| Код, схемы данных, миграции | Без встроенных секретов и пользовательских записей |
| ТЗ, C4/UML, ADR, план, GitFlow | Описание продукта; без цитат интервью и личной биографии |
| Каталог интеграций | Название сервиса означает поддержку адаптера, а не наличие аккаунта/счёта у владельца |
| Тесты, fixtures, демонстрации | Полностью синтетические люди, события и суммы; не замена имён в реальном дневнике |
| `.env.example`, примеры конфигурации | Только пустые значения/очевидные заглушки; никаких действующих ID и токенов |
| Исследования и замеры | Публичные источники; обезличенный тестовый стенд и синтетические входные данные |
| Медиа и зависимости | Собственные/разрешённые лицензией материалы; источник и условия использования проверены |
| Релизы | Чистая сборка; без локального профиля, индекса, копий, логов и секретов |

## Не публикуется

- Исходные интервью, переписка с ИИ, личные причины разработки и цитаты владельца.
- Реальные самооценки, выводы о личности/здоровье, привычки, люди, события, фото, голос, расшифровки и резюме.
- RAG-записи, embeddings, индексы и служебные метаданные личных данных: они тоже могут раскрывать содержание.
- Банковские операции, выписки, портфель, налоговые сведения, номера счетов, долги, суммы доходов и расходов владельца.
- Геопозиция, история приложений/сайтов, данные сна/часов, реальные региональные настройки аккаунта и идентификаторы устройств.
- Токены бота, ключи API, пароли, cookie, сессии, signing keys, provisioning profiles и дампы сетевого трафика.
- Локальные базы, резервные копии, модели и кэши. Для моделей публикуются разрешённые ссылки, версии, лицензии и контрольные суммы после выбора.
- Скриншоты рабочего профиля, реальные данные в ошибках, CI-логах, PR-описаниях или тестовых отчётах.

## Локальная структура

- `private/` — интервью, персональные решения и рабочие копии документов до обезличивания.
- `local/` — персональные настройки разработчика/установки.
- `var/` — данные приложения, медиа, модели, кэш, логи и резервные копии.

Все три каталога исключены из Git целиком. Публичные документы не должны ссылаться на существование конкретных файлов внутри них. Исходные интервью сохранены локально; их хранение здесь не является резервной копией.

Файлы на локальном диске не становятся допустимыми к отправке внешнему ИИ или загрузке в issue только из-за `.gitignore`.

## Проверка перед коммитом и публикацией

1. Добавлять файлы по явному списку; просмотреть `git diff --cached --name-status` и полный `git diff --cached`.
2. Проверить текст, вложения, примеры, журналы и метаданные на персональные сведения и секреты. Автоматический поиск — вспомогательная проверка, не доказательство отсутствия утечек.
3. Проверить отсутствие `private/`, `local/`, `var/`, файлов окружения и ключей среди отслеживаемых: `.gitignore` не скрывает ранее закоммиченные файлы.
4. Проверить лицензии новых материалов и содержимое сборочного архива, если он публикуется.
5. Применять ту же проверку к сообщениям коммитов, PR/issues, CI и заметкам релиза. Не добавлять личные объяснения изменений.

Не использовать `git add -f` для локальных данных. Разрешение ИИ на автоматическое слияние и релиз действует только для материалов, прошедших эту проверку.

## Если данные уже попали в Git

Остановить дальнейшую публикацию, определить коммиты/артефакты и состав сведений. Секреты отозвать и заменить. Удаление файла следующим коммитом или смена видимости не удаляют его из истории и уже сделанных копий. План очистки истории и внешних артефактов готовится отдельно с учётом совместной работы; не обещать полного удаления чужих копий.
