# R1 — проект первого рабочего выпуска

> Baseline 1.0: нормативные значения и закрытые решения — [BR-01–10](../requirements/baseline-rules.md). Этот документ — вспомогательное представление; прежние пометки «предложено/уточнить» не отменяют зафиксированный baseline. Реализуемость интеграций подтверждается отдельными gates.

Статус: baseline принят для реализации; начат доменный и прикладной слой State. R1 ещё не выпущен.

## Пользовательский путь

Вход в macOS → запуск фонового ядра → открытие персонажа → частичная отметка состояния → сохранение → новый баланс/unknown → переход к истории и источнику. Закрытие окна сохраняет фон; отдельный Stop завершает всю систему. Ошибка сервиса/неизвестный источник показаны явно.

## Состав

Profile, State, read-model Character и минимальные Operations/Notifications. Никаких фиктивных чисел энергии при первом запуске. Накопленный опыт и квесты ещё не работают: соответствующий раздел скрыт либо явно отмечен как будущий, не выдаётся за завершённую функцию.

Предлагаемый минимум Telegram R1: привязка владельца, отметка четырёх самооценок, краткий просмотр состояния и напоминания. Голос/фото получают статус недоступной функции до соответствующего модуля; обещание полноценного бота в R1 не дано.

Учёт Mac требуется с начала, но SP-01 остаётся блокировкой объёма: при недоступности Apple-источника необходимо решение пользователя, а не незаметная замена. Watch разрабатывается отдельным потоком и не блокирует выпуск по согласованию.

## Вертикальные задачи

1. Закрыть временные правила State и минимальные ОС; выбрать стек/хранилище через ADR и эксперименты.
2. Собрать чистые Domain/Application, фейковые порты и архитектурные/unit проверки.
3. Добавить реальное хранилище с revision/idempotency, миграцией и интеграционными тестами.
4. Реализовать macOS-путь записи/просмотра с UI/E2E тестом синтетического профиля.
5. Добавить фон, Telegram, квоты, сон/возобновление и fault injection.
6. Проверить установку, полную остановку, disk budget, backup/restore и состав публикации.
